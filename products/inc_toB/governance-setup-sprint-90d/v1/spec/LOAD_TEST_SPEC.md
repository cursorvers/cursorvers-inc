## 2. Apps Script の制限事項

### 2.1 実行時間制限

| アカウント種別 | 最大実行時間 | 備考 |
|--------------|-------------|------|
| 無料アカウント | 6分 | 1回のスクリプト実行あたり |
| Google Workspace | 30分 | 有料プラン利用時 |

**対策**:
- 長時間処理はバッチ分割（1回あたり100行処理など）
- 継続トリガーでレジューム処理を実装
- PropertiesService で処理状態を保存

### 2.2 トリガー制限

| 制限項目 | 制限値 | 備考 |
|---------|--------|------|
| プロジェクトあたりトリガー数 | 20個 | 時間ベース + イベントベース合計 |
| 1日あたりトリガー実行 | 90分 | 累積実行時間 |
| 同時実行数 | 30 | ユーザーあたり |

### 2.3 API呼び出し制限

| API | 日次制限 | 備考 |
|-----|---------|------|
| Spreadsheet read/write | 無制限 | ただしセル数制限あり |
| UrlFetch | 20,000回/日 | 外部API連携時に注意 |
| PropertiesService | 50,000回/日 | 状態管理に使用 |
| ScriptCache | 500回/秒 | 高頻度アクセス時に注意 |

### 2.4 その他の制限

| 制限項目 | 制限値 |
|---------|--------|
| スクリプトファイルサイズ | 1MB |
| カスタム関数実行時間 | 30秒 |
| メール送信 | 100通/日（無料）, 1,500通/日（Workspace） |

## 3. Google Sheets の制限事項

### 3.1 セル数制限

| 項目 | 制限値 | 備考 |
|------|--------|------|
| 1シートあたりセル数 | 10,000,000 | 1000万セル |
| 1ワークブックあたりセル数 | 10,000,000 | 全シート合計 |
| 列数 | 18,278列 | A〜ZZZ |

### 3.3 数式・関数制限

## 4. ボトルネック予測箇所

### 4.1 高リスク箇所

| 箇所 | リスク | 発生条件 | 影響 |
|------|-------|---------|------|
| 案件インポート処理 | 高 | 50件以上の一括インポート | タイムアウト（6分制限） |
| QUERY関数での集計 | 中 | 10,000行超のデータ参照 | シート操作の遅延 |
| 外部API連携 | 高 | UrlFetch 20,000回/日超過 | エラー発生 |
| 同時編集 | 中 | 5名以上の同時アクセス | 競合・データ破損リスク |

### 4.2 パフォーマンス劣化パターン

```
案件数  | 応答時間 | 状態
--------|---------|------
< 1,000 | 即時    | 良好
1,000〜 | 1-3秒   | 許容範囲
5,000〜 | 3-10秒  | 注意
10,000〜| 10秒超  | 対策必要
```

### 4.3 メモリ関連

| 処理 | メモリ上限 | 対策 |
|------|----------|------|
| getValues() | 大規模配列で問題発生 | 範囲を分割して取得 |
| setValues() | 同上 | バッチ書き込み |
| JSON.parse() | 50MB以上で問題 | ストリーミング処理 |

## 6. スケールアウト時の対応策

### 6.1 シート分割戦略

#### 時系列分割（推奨）

```
案件管理_2025.gsheet  ← 2025年度の案件
案件管理_2024.gsheet  ← 2024年度の案件（アーカイブ）
案件管理_2023.gsheet  ← 2023年度の案件（アーカイブ）
```

**実装手順**:
1. 年度末に新シートを作成
2. 旧シートは読み取り専用に変更
3. 集計は IMPORTRANGE で横断参照

#### カテゴリ分割

```
案件管理_進行中.gsheet   ← アクティブ案件
案件管理_完了.gsheet     ← 完了案件
案件管理_保留.gsheet     ← 保留・中止案件
```

### 6.2 アーカイブ戦略

#### 自動アーカイブスクリプト（例）

```javascript
function archiveOldCases() {
  const SOURCE_SHEET = '案件管理';
  const ARCHIVE_SHEET = '案件管理_アーカイブ';
  const DAYS_THRESHOLD = 180; // 180日以上前の完了案件

  const ss = SpreadsheetApp.getActiveSpreadsheet();
  const source = ss.getSheetByName(SOURCE_SHEET);
  const archive = ss.getSheetByName(ARCHIVE_SHEET);

  const data = source.getDataRange().getValues();
  const headers = data.shift();
  const today = new Date();

  const toArchive = data.filter(row => {
    const completedDate = new Date(row[/* 完了日列 */]);
    const daysDiff = (today - completedDate) / (1000 * 60 * 60 * 24);
    return row[/* ステータス列 */] === '完了' && daysDiff > DAYS_THRESHOLD;
  });

  if (toArchive.length > 0) {
    archive.getRange(archive.getLastRow() + 1, 1, toArchive.length, toArchive[0].length)
           .setValues(toArchive);
    // 元シートから削除
    // ...
  }
}
```

### 6.3 パフォーマンス最適化

#### 読み取り最適化

```javascript
// Bad: 行ごとに読み取り
for (let i = 1; i <= lastRow; i++) {
  const value = sheet.getRange(i, 1).getValue(); // 遅い
}

// Good: 一括読み取り
const values = sheet.getRange(1, 1, lastRow, lastCol).getValues(); // 速い
for (let i = 0; i < values.length; i++) {
  const value = values[i][0];
}
```

#### 書き込み最適化

```javascript
// Bad: セルごとに書き込み
for (let i = 0; i < data.length; i++) {
  sheet.getRange(i + 1, 1).setValue(data[i]); // 遅い
}

// Good: 一括書き込み
sheet.getRange(1, 1, data.length, 1).setValues(data.map(v => [v])); // 速い
```

### 6.4 代替アーキテクチャ

月間100件超が継続する場合、以下を検討:

| 選択肢 | コスト | 難易度 | 適用シナリオ |
|--------|-------|--------|-------------|
| BigQuery連携 | 中 | 高 | 大量データ分析が必要 |
| Firestore移行 | 中 | 高 | リアルタイム同期が必要 |
| Airtable移行 | 低 | 低 | UIの改善も必要 |
| 専用SaaS導入 | 高 | 低 | 運用負荷を下げたい |

## 8. テスト計画

### 8.1 負荷テストシナリオ

| シナリオ | 操作 | 期待結果 |
|---------|------|---------|
| 単体インポート | 1件のインポート | 5秒以内に完了 |
| バッチインポート | 10件の一括インポート | 60秒以内に完了 |
| 大量データ読み取り | 5,000行の案件一覧表示 | 3秒以内に表示 |
| 同時アクセス | 5名同時編集 | データ競合なし |
| 連続処理 | 100件の連続処理 | 6分以内に完了 or 適切に分割 |

### 8.2 テスト環境

- テスト用スプレッドシートを別途作成
- 本番データのコピーは禁止（個人情報保護）
- ダミーデータ生成スクリプトを使用
